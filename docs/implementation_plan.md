# 外企信息集合网站实施计划

## 1. 产品定位

不要只做“外企官网导航”，而要做“中国外企岗位与福利情报库”。核心价值是帮助求职者快速判断：这家公司是不是真外企、当前有没有真实岗位、岗位是不是正式员工、福利是否值得投、有哪些小众外企值得发现。

建议一句话定位：专门帮中国求职者发现真实外企正式岗位的网站。

## 2. 目标用户

1. 想进外企但不知道有哪些公司的应届生和 1-5 年经验求职者。
2. 想从民企/互联网转外企、看重稳定福利和 work-life balance 的职场人。
3. 想找上海、北京、苏州、深圳、广州外企岗位的人。
4. 想找小众高质量赛道的人，例如宠物食品、动物保健、家具家居、检测认证、香精香料、半导体设备、商业地产、物流供应链。

## 3. 核心痛点

1. 外企岗位分散在 Workday、SuccessFactors、Oracle、SmartRecruiters、公司官网、LinkedIn、BOSS、猎聘、51job 等平台。
2. “外企”关键词被污染，很多岗位其实是外包、派遣、供应商岗位。
3. 福利信息不透明，大家真正关心的是年假几天、几薪、是否补充公积金、商业保险是否覆盖家属、是否混合办公、是否做四休三。
4. 大众只知道少数大公司，很多小众外企被低估。
5. 招聘网站按岗位搜索强，但按“公司质量 + 行业 + 福利 + 合同类型”筛选弱。

## 4. MVP 范围

第一版先不要追求全网自动化，重点做一个可信、好用、可迭代的数据库。

### 4.1 公司库字段

- 公司英文名
- 中文名/品牌名
- 行业
- 细分赛道
- 国家/地区
- 中国重点城市
- 官网招聘入口
- 第三方招聘入口
- 适合关注岗位
- 福利标签
- 合同类型提醒
- 数据可信度
- 最近更新时间

### 4.2 岗位库字段

- 岗位名
- 公司
- 城市
- 行业
- 职能
- 来源平台
- 申请链接
- 发布时间/抓取时间
- 是否疑似外包
- 是否正式员工
- 福利关键词
- 备注

### 4.3 福利情报库字段

- 公司
- 福利项目
- 具体数字/制度
- 适用范围
- 来源链接
- 来源截图/证据
- 可信度等级
- 更新时间

重点福利标签：五险一金、补充公积金、商业保险、商业保险覆盖家属、年假 15 天+、13 薪/14 薪/15 薪/16 薪、员工股票/RSU/ESPP、混合办公、弹性上下班、不打卡、做四休三、周末双休、员工折扣、员工购车/内购。

## 5. 页面规划

### 5.1 首页

- 搜索框：公司名、岗位名、福利关键词
- 城市筛选：上海、北京、苏州、深圳、广州、杭州、成都、大连、无锡
- 行业入口：科技、半导体、医药、宠物、家具、快消、金融、咨询、检测认证等
- 热门福利入口：年假 15 天、补充公积金、商业保险覆盖家属、员工股票、混合办公、做四休三
- 今日新增外企岗位
- 小众好公司专题

### 5.2 公司列表页

筛选维度：行业、城市、国家/地区、是否有官网岗位、福利标签、是否高可信福利、是否有正式员工岗位。

列表展示：公司名、行业/细分赛道、中国重点城市、当前岗位数、福利标签、招聘入口、最近更新时间。

### 5.3 公司详情页

核心模块：公司简介、所属行业和细分赛道、中国主要办公城市、官网招聘入口、当前在招岗位、福利待遇、合同类型提醒、常见岗位方向、面试/投递注意事项、相似公司推荐。

### 5.4 岗位列表页

筛选维度：公司、行业、城市、职能、来源、福利标签、是否正式员工、是否疑似外包、发布时间。

岗位卡片展示：岗位名、公司、城市、来源、申请链接、福利关键词、合同类型提示、抓取时间。

### 5.5 投稿页

用户可以投稿公司福利、岗位是否外包、面试经验、内推信息、JD 截图或链接。投稿必须审核，避免虚假信息污染数据库。

## 6. 数据策略

### 第一阶段：人工整理 + 半自动更新

目标：先建立 300-500 家外企公司库。

数据来源：公司官网 Careers、Workday/SuccessFactors/Oracle/SmartRecruiters 等 ATS 页面、LinkedIn Jobs、BOSS 直聘、51job、猎聘、智联招聘、公司公众号招聘信息、用户投稿。

第一阶段不强求抓取所有岗位，只要保证每家公司都有可信招聘入口和基础画像。

### 第二阶段：自动抓取官网岗位

优先抓取可公开访问且结构稳定的来源：公司官网搜索页、Greenhouse、Lever、SmartRecruiters、Workday 可公开职位页、SuccessFactors 可公开职位页、Oracle Cloud Careers 可公开职位页。

抓取频率：热门公司每天 1 次，普通公司每周 2-3 次，小众公司每周 1 次。

### 第三阶段：福利与合同类型识别

对岗位 JD 做关键词识别：

- 福利关键词：五险一金、补充公积金、商业保险、15天年假、16薪、股票、混合办公、弹性办公、做四休三
- 风险关键词：外包、派遣、第三方合同、供应商、驻场、服务某外企客户、BPO、Vendor

每条福利信息标可信度：

- A：公司官网/官方 JD 明确写出
- B：认证招聘平台 JD 写出
- C：多名用户投稿一致
- D：单条用户投稿，待验证

## 7. 数据库设计建议

### companies

id, name_en, name_cn, industry_id, sub_sector, country_region, city_focus, career_url, company_summary, status, created_at, updated_at

### jobs

id, company_id, title, city, function, source_platform, source_url, posted_at, scraped_at, employment_type, contract_type, is_outsourcing_suspected, raw_description, status

### benefits

id, company_id, job_id, benefit_type, benefit_value, applies_to, source_url, evidence_text, confidence_level, verified_at

### industries

id, name, description

### submissions

id, user_id, company_id, type, content, evidence_url, evidence_file, status, reviewed_by, reviewed_at

## 8. 技术方案建议

### 快速 MVP

- 前端：Next.js
- 后端：Next.js API Routes 或 FastAPI
- 数据库：PostgreSQL + Prisma
- 搜索：Postgres full-text search，后续接 Meilisearch/Typesense
- 定时任务：GitHub Actions / Cloud Run Jobs / Vercel Cron
- 部署：Vercel + Supabase，或 Cloud Run + Cloud SQL

### 抓取服务

- 普通静态页面：HTTP fetch + HTML parser
- 动态页面：Playwright
- 反爬强平台：不硬爬，放跳转链接或人工维护
- 每次抓取保存原始 URL、抓取时间、岗位摘要和 hash，用于去重

### 后台管理

必须有后台，否则数据质量会很快失控。

后台功能：公司增删改查、岗位审核、福利证据审核、投稿审核、外包风险标记、批量导入 CSV、数据更新时间监控。

## 9. MVP 里程碑

### 第 1 周：数据和信息架构

- 整理 150-300 家外企公司库
- 定义行业分类和福利标签
- 确定数据库表结构
- 完成首页、公司页、岗位页原型

交付物：公司 CSV、字段字典、低保真原型。

### 第 2 周：基础网站

- 搭建 Next.js 项目
- 导入公司库
- 做公司列表页和公司详情页
- 做行业筛选、城市筛选、福利筛选
- 做招聘入口跳转

交付物：可访问 MVP 网站。

### 第 3 周：岗位聚合

- 对 20-50 家官网 Careers 做抓取 PoC
- 建岗位表
- 展示在招岗位
- 增加岗位详情跳转
- 增加抓取时间和来源标识

交付物：可展示真实岗位的公司详情页。

### 第 4 周：福利和外包识别

- 建福利标签体系
- 对 JD 做关键词识别
- 加“疑似外包/正式员工”提示
- 增加用户投稿入口
- 增加后台审核

交付物：具备差异化价值的外企情报库。

## 10. 早期获客方式

1. 小红书：外企清单、外企福利盘点、小众外企专题。
2. 公众号：上海外企岗位周报、行业地图、避坑指南。
3. 即刻/脉脉/知乎：发布“外企正式岗位筛选器”。
4. 社群：按行业建立外企求职群，例如药企群、半导体群、宠物赛道群。
5. SEO：围绕“上海外企招聘”“外企福利”“外企正式员工岗位”“补充公积金外企”等关键词做长尾页面。

## 11. 商业化路径

免费层：公司库浏览、招聘官网入口、基础行业筛选、部分岗位展示。

会员层：高级福利筛选、岗位订阅提醒、外包风险过滤、福利证据查看、每周外企岗位报告。

服务层：简历优化、外企面试辅导、行业求职路线咨询、内推社群。

B 端：外企雇主品牌页、招聘广告、精准职位推广、人才洞察报告。

## 12. 风险和应对

- 数据维护成本高：先半自动，优先维护高价值公司和热门城市，不追求全网全量。
- 招聘平台反爬：不硬碰强反爬平台，优先抓官网和 ATS；对 BOSS/猎聘/51job 只做搜索入口和人工标注。
- 福利信息真实性：每条福利都标来源和可信度，不把用户投稿当官方事实。
- 法务和版权风险：不复制完整 JD，大量使用摘要、标签和原始链接；尊重 robots 和平台规则。
- 产品容易变成导航站：核心差异化必须是“正式岗位识别 + 福利标签 + 小众外企发现 + 岗位提醒”。

## 13. 下一步建议

1. 先把当前 CSV 导入数据库或 Airtable/飞书多维表。
2. 补齐 300 家公司，尤其是上海、苏州、北京、深圳、广州。
3. 选 30 家官网岗位可抓取的公司做 PoC。
4. 做第一版网站，只上线公司库、行业分类和招聘入口。
5. 第二版再上线岗位抓取和福利标签。
